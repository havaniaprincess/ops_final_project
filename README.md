# Итоговый проект по курсу ""Инфраструктура и администрирование"

Итоговый проект, призванный показать компетенции Operation systems, на примере простого http-сервера.

## Краткое описние

HTTP-сервер написанный на `RUST`, с использованием библиотеки `axum` для роутинга endpoint-ов. Для логирования использовалась библиотека `log`. Сервис предоставляет простой сайт и несколько базовых get-ендпоинтов.

## Сам сервис

Что сервис умеет для пользователя:

- **Back-end** для сайта. На данный момент там простенкий сайт позволяющий следить за наложением событий в проекте друг на друга, конда они начинаются и заканчиваются.(endpoint-ы для `html`, `js`, `css`)
- **Other Endpoints**
    - `/health` - возвращает статус 200 - Success
    - `/temp_converter?celsius=<f64>` - возвращает переведенные в фарингейты цельсии
    - `/version` - возвращает форматированную строку содержащую версию сервиса, версию компилятора и автора.

Что сервис еще умеет внутри:

- `unit-test-ы` - сервис полностью покрыт 34-мя тестами
- `logging` - сервис логирует каждый запрос, по какому endpoint-у он пришел, какой ответ получил(статус) и за сколько был выполнен. Запись логов в файл выполняется в отдельном потоке

## Окружение

Для запуска сервиса требуется система сборки `cargo` которую можно установить по инструкции разработчиков: [Rust Book. Installation.](https://doc.rust-lang.org/book/ch01-01-installation.html)

В проекте находится файл `Cargo.toml` где и указаны все настройки проекта, включая зависимоти, настроки сборки, тестов и прочее. При компиляции компилятор все скомпилирует в папку `target` бинарник бедет лежать по пути `./target/debug/ops_app` или `./target/release/ops_app`. Поэтому это и есть окружение проекта.

## Docs

Компилируются и открываются с помощью команды 

```
cargo doc --open --no-deps
```

## Запуск сервиса

Бинарный файл после компиляции находится в `./target/debug/ops_app` или `./target/release/ops_app` в зависимости от типа компиляции. Компиляция делается по средствам команды:

```
cargo build --release // по-умолчанию debug
```

Для того чтобы скомпилировать и запустить существует команда `run`

```
cargo run --release
```

## Запуск тестов

Для этого понадобится команда

```
cargo test
```

## Переменные окружения

Список переменных окружения требуемых сервису:

- `LOG_FILE` путь к файлу с логами(по умолчанию `logs/server.log`)
- `APP_PORT` порт сервиса(по умолчанию `3000`)
- `CARGO_PKG_VERSION` версия сервиса, сборщик создаст сам
- `RUSTC_VERSION` версия компилятора, создается при сборке кодом в файле `build.rs`
- `CARGO_PKG_AUTHORS` автор сервиса, сборщик создает сам
- `RUST_LOG` уровень логирования(по умолчанию `info`)

Остальные переменные требуемые при деплое:

- `APP_NAME` имя приложения(бинарного файла)
- `DOMAIN` и `EMAIL`
-  `HTTP_PORT` и `HTTPS_PORT`

## CI on GitHub

GitHub при каждом pull request и push выполняет тестирование версии, которое состоит из:

- `fmt`: тест форматирования кода
- `clippy`: статический анализ кода, поиск неэффективностей, потенциальных ошибок
- `test`: тестирование юнит тестами.
- `docs`: компиляция документации
- `coverage`: тест покрытия кода тестами
- `audit`: тест на уязвимости, нарушение лицензий

## CD on GitHub

GitHub запускает деплой на сервере посредством ssh и сам после отработки деплоя проверяет работоспособность сервиса(endpoint-ы `/health` и `/version`). На виртуальной машине настроен доступ по данному ключу только для деплоя коммитов. Если используемы ключ пытается выполнить что-то другое, у него не получится, скрипт, который обрабатывает все коннекты по ключу не даст запустить скрипт деплоя(`./deploy.sh`).

### `./deploy.sh`

Умеет:

- поднять сервис и ансамбль докеров.
- выключить все
- рестартануть
- показать логи сервиса и логи докеров

### `./DEPLOY.md`

В данном файле собрана информация о первичной настройке VM

## Варианты запусков

### Только сервис

```
cargo run -- release
```

Требуется установленный сборщик `cargo`. Сервис будет доступен по пути `localhost:3000`

### Ансамбль Docker'ов

```
cp .env.example .env
docker compose up -d --build nginx app
```

В `.env` поменять нужные параметры, например, `DOMAIN=localhost` перед запуском.

Требуется создать самоподписанные сертификаты и положить в `certbot/conf/live/$DOMAIN`.
